## 摘要

1. `human-writing` 的生成态管的不是「把清理规则提前读一遍」，而是五件事：**材料、说话位置、推进、结构、中文句法**。它明确规定 `references/revision.md` 只在初稿完成后加载（`SKILL.md:46`、`revision.md:3`），并且 SKILL.md 里的交付禁令也「留到初稿完成后再逐项检查」（`SKILL.md:48`）。清理态与生成态在这个项目里是**被主动隔开的两个文件与两个时点**。
2. 它的保障机制是分层的：一处真硬停（非虚构列不出五件材料就不许输出长文正文，`SKILL.md:28`）、两份动笔前清单（`SKILL.md:80-86` 五问、`forum-prose.md:337-349` 四问）、一份加载纪律（按任务读取、清理规则延后）、一张冲突优先级表（`SKILL.md:50-60`）、以及一个**事后**运行的脚本门禁（`check_prose.py`，失败即退出码 1）。没有动笔前的自动拦截。
3. 最大弱点：材料门槛是**自证式**的。五件材料只要求「先在内部逐条写出」，并明确「不要把这些内部检查交给用户」（`SKILL.md:26,36`），没有任何强制证据产物或外部校验。一个愿意撒谎的模型可以直接跳过关口而不留痕迹。
4. 可借的生成态骨架有十五条（第 3 节 A1–A15），核心是「材料门槛 + 说话位置五问 + 每段必须新增一件东西 + 不从提纲/分类开始 + 主干早出」；另有一条工具边界规则（警告项不替作者决定文体）值得整条吸收。
5. 不能借的主要是虚构侧全部规则（人物目标、场景变化、对白、视角、设定投放、场景与概述交替、结尾留后果），以及中文互联网平台体裁惯例（知乎体/长帖体/公众号体）与中文公司黑话词表。
6. 关于与 lieflat 的六条矛盾：`human-writing` **从未点名 lieflat，也从未给出任何统计辩护**。它宣告的判据是「像一个具体的人在说话」（仓库 description、`README.md:20`、`SKILL.md:8`），禁的是「修辞动作」而不是「高频字符串」（`SKILL.md:140`、`README.md:65`）。全文 `频率` 零命中，唯一的统计成分是脚本警告层的两个阈值（句长变异系数、连词密度），而这两个阈值在代码里**没有任何出处注释**，只有 `CHANGELOG.md:21` 一句「阈值依据 CCL 2023 人机中文对照研究」——该依据无法锁定到具体文献。
7. 最能说明问题的一处对照：`human-writing` 的借喻禁词表（仓库/抽屉/温度/死亡/坍塌/浪潮/钥匙/底座，`SKILL.md:151`；`revision.md:82`；`check_prose.py:192-200` 的 `METAPHOR_FIELDS`）与 lieflat 自己承认的**第六次测量失误**高度重合——lieflat 原正则是一张写死的 11 词表（仓库/抽屉/温度/钥匙…），改测构式后才发现「人类比 AI 多 2.4 倍，方向与预设相反」（`RESEARCH.md` L124、L253）。也就是说：`human-writing` 今天绝对禁止的那批借喻，正是 lieflat 已经用实测撤回的那批。

## 1. 它的生成态规则实际管的是哪几件事

结论：管五件事，且**不是**「把清理规则在生成时又读一遍」。下面按文档给出的先后顺序列出，每条给原文与位置。

### 1.1 材料：这一关决定「允不允许写」，先于提纲和动笔

这是整个 Skill 的第一关，标题就叫「第一关先看作品靠什么站住」，开头一句直接封死绕行：

> 「这一步先于提纲和动笔。用户要求的字数不能跳过它。」（`SKILL.md:14`）

具体条款：

- **分清材料身份**（`SKILL.md:16-20`）：现实作品靠「用户明确提供的经历、事实、数字、动作、原话与判断」与「已经查到并能核验的案例、数据、产品流程、人物经历与时代条件」；虚构作品靠「作者获准创造的事件、人物动作与场景变化」；混合创作先分开两部分。
- **什么不算材料**（`SKILL.md:22`）：「模型临时想出的『比如有个人』、没有来源的典型场景、常识推演、抽象观点的后果、比喻与同义改写，都不能拿来撑篇幅。」原文还给了一个判定例：把「记录方便」「声音保留状态」「检索找回旧内容」各解释五遍，手里仍然只有三条材料。
- **量化门槛**（`SKILL.md:26`）：「非虚构作品计划达到一千二百字时，先在内部逐条写出至少五件具体材料，并注明它来自用户哪句话或哪份可靠来源。只写一个概括性的类别不算。五件材料还要能组成一条实际过程，不能是五句相邻的道理。」注意三个限定：≥1200 字才触发、必须写明来路、五件之间要有过程关系。
- **材料身份五分类**（`reality.md:16-28`）：可靠来源能直接证明的事实／机构或当事人自述／旁人回忆和媒体概括／作者推断／目前不知道的地方；并要求「记录时间、来源和口径」。
- **现实观点稿的高频错误被单独拦住**（`SKILL.md:38`）：三条抽象想法 + 一千多字要求，仍然只有三条材料，不许「分别补上用途、意义、风险和未来，再写成十几段」。
- **虚构侧的对位门槛**（`SKILL.md:24`）：「每个主要段落或场景仍要有动作、选择、关系变化、信息变化或后果。只换景色和说法，没有事情发生，也不能拿来撑篇幅。」

这一条是纯生成态：它决定要不要下笔、写到多长。清理态无法补出材料，`revision.md` 也只能反过来做「压缩试验」（`revision.md:44`：删掉三分之一后事实、动作、判断几乎没变，就是在注水）。

### 1.2 说话位置：谁在说、他凭什么知道、对谁说

标题即「动笔前先找到说话位置」，要求「在内部回答下面五件事，不把答案原样交给用户」（`SKILL.md:80`）：

1. 谁在说这件事。他凭什么知道，又有哪些地方只是在推测。（`SKILL.md:82`）
2. 什么事情让他现在想说。（`:83`）
3. 手里有哪些能托住文章的东西。优先找动作、数字、时间、地点、原话、失败、代价与后来结果。（`:84`）
4. 他对哪一点有明确判断。这个判断依据什么，又到哪里为止。（`:85`）
5. 读者知道上一段以后，最自然会追问什么。（`:86`）

`forum-prose.md:18-42` 把它展开成可执行的位置定义：

- 四种合法位置：「他可能亲自经历过，可能做过调查，可能熟悉这个行业，也可能只是认真查完资料以后形成了判断。四种位置都可以。不能把查资料写成亲历，也不能把猜测写成内幕。」（`forum-prose.md:22`）
- 说话位置的证据是「知识的来路」，列了五类。哪件事让作者留意到这个问题／一开始怎样理解、后来被哪条材料纠正／哪个细节只有做过这件事的人才会注意／哪块资料互相打架、作者怎样取舍／哪个判断只是个人看法。「每篇挑一两项自然出现。全部凑齐会变成新模板。」（`forum-prose.md:28-34`）
- 对谁说：「不要同时向『所有人』演讲。把读者想成一个聪明、感兴趣、对背景不熟的普通人。」「向读者说话不等于频繁喊『大家』『朋友们』。真正的交流发生在解释顺序里。」（`forum-prose.md:40-42`）

这条同样只属于生成态：它是「以什么身份、对着谁、按什么顺序说」的决策；清理态只能在事后判「这一段像不像有人在场」（`revision.md:19-30` 第一遍）。

### 1.3 推进：每段必须新增一件东西，后段接住前段

`SKILL.md:110-112`：

> 「一段先完成眼下这一件事。」
> 「新段落必须增加一件新东西。新的事实、新的动作、新的例子、新的区别或新的后果都可以。同一观点改换说法不算推进。」
> 「后一段接住前一段留下的问题。推进靠材料和因果，不靠『更深一层』『真正的问题』之类路标。」

`forum-prose.md:44-58` 给出五种「自然推进」：先讲发生了什么→读者追问为什么；先给判断→读者追问凭什么；先讲处境→读者追问后来怎么办；先讲通常情况→读者追问这次哪里特殊；先讲结果→读者追问中间出了什么岔子。并特别说明「这些关系可以反复交替。不要把它们排成固定的五段」，岔话「也要从眼前的词长出来」，且「讲到借款忽然想起文明兴衰，通常只是在炫耀联想能力」。

这条既是生成态也在清理态复现（`revision.md:32-48` 第二遍「看文章有没有往前走」），但**作为生成态才有意义**：清理态面对已经跑偏的结构只能重写。文档也承认这一点——`revision.md:40` 的处置是「删到文章长度与材料相称，不替目标字数保稿」。

### 1.4 结构：不预先搭架子，分类不能代替文章

`SKILL.md:108-109`：

> 「开头尽快碰到事情。可以直答，可以讲刚发生的一幕，也可以从一个反常的小事实说起。不要预告全文结构。」
> 「除非用户明确要清单或教程，不要先把题目命名成两个成本、三层原因、四个阶段。分类应当来自材料，不能拿分类代替文章。」

配套条款：知识只在需要时进入（`forum-prose.md:95-103`：「不要先把背景一次倒完。读者问到钱，算钱。人物碰到一条制度，再解释制度。」）、长文绕出去回来要多带一件东西（`:101`）、结尾不升华（`SKILL.md:120`：「写到事情已经讲完就停。不要强装升华、首尾呼应或时代意义……不要在末段重新摘要全文。」）、`formats.md` 按体裁给出十一种形式的默认结构。

### 1.5 中文句法：主干早出、顺势接话、长短有差、白话打底

`forum-prose.md:60-93` 三条核心：

- 主干早出：「普通中文经常先说人做了什么，再补原因、时间、条件和例子。」反例是「在经历了长达数年且始终缺乏稳定收入来源的反复尝试以后，最终促使他改变原有方向的，是一次来自老同事的邀请」。
- 顺势接话：「第一句把『收据』送到句尾，后面顺手接住它。」「同一个人连续做几件事，指向清楚时可以省去重复的『他』。」同时提醒「自然不等于含糊」。
- 不要英语式长定语：「不要把英语式层层嵌套搬到『的』字前面。」

`forum-prose.md:115-127` 白话与古意的取舍：单双音节词按说话者与场合选、「成语和典故只在三个条件同时成立时留下」、古意来自照应和收束而不是临时请一句古诗盖章。

`forum-prose.md:129-162` 节奏与四条可量化的模型腔修法：句长要有高低差、删一半连词、名词化还原成动词、该重复就重复。

### 1.6 它没有做的那件事：把清理规则搬进起草

这是本报告最要紧的一条结论，证据有三处，方向一致：

- `SKILL.md:46`：「初稿完成后再读取 `references/revision.md`。**不要在动笔前加载详细审稿规则。**」
- `SKILL.md:48`：「创作时以正向目标为主，已经写在本文件里的交付禁令**留到初稿完成后再逐项检查**。」
- `revision.md:3`：「这份文件只在初稿完成以后读取。**它不能参与第一稿生成。**」

也就是说，`human-writing` 的答案是：生成态**不应该**带着禁令清单写字，而应该带着「材料 + 说话位置 + 推进 + 句法」这四个正向目标写字，禁令留到成稿后清。它给出的理由是注意力竞争——`SKILL.md:48` 紧接着写「不要为了保险一次加载全部参考文件，只读当前任务确实命中的部分」。

唯一横跨两侧的是「翻案腔」：禁令写在 `SKILL.md:142`（成稿绝对不能出现），但给模型的动作指令是生成式的——「判断直接从正面下，先给判断，再给依据」。这条恰好说明了生成态设计的判据：**如果一条规则的修法是「重新下一个判断」，它就必须进生成态；如果修法只是「换一种说法」，它才适合留在清理态。**

## 2. 它靠什么保证规则在起草时真的被用上

答案是「三层提示 + 一处硬停 + 一个事后脚本」，没有动笔前的自动拦截。逐项列证据。

### 2.1 硬停：唯一的一处结构性阻断

`SKILL.md:28` 原文：

> 「非虚构稿列不出五件，就先别写长稿。**这一轮不能输出标题和长文正文。**目标字数、用户催促和『直接写』都不能把材料变多。」

这句话满足「材料不够就不许动笔」的形式要求：它禁的不只是「别写长」，而是具体到**不许输出标题和长文正文**，并且预先否掉了三种施压路径（目标字数、催促、直接写）。`SKILL.md:90` 还有第二处停：「现实材料不够时先停在这里。」`SKILL.md:88` 有回退：「现实稿的第三项太少，回到开稿前的材料检查。」

但它带着三条明确的出口（`SKILL.md:30-34`），所以是「硬停 + 限定绕行」而不是绝对门禁：

1. 事实型题目有公开材料可查时，**先研究，研究后重新计数**；「可用检索工具却没有检索，仍然算没有材料」。
2. 依赖用户体验或私人判断时，「一次问完最多三个问题，此时不要同时交稿」。
3. 用户明确不许追问时：能研究的先研究，重新计数；「研究之后仍然不足五件，缩小题目，最多交一篇六百字左右的短答。宁可明显短于目标字数，也不能用假例子和重复解释填满」。

`SKILL.md:98` 是这条原则的收口句：「篇幅是目标，材料边界是底线。」

### 2.2 动笔前清单：两份，都很短

- 五问（`SKILL.md:80-86`，见 1.2）。
- 「动笔前最后看一眼。**只检查四件事**」（`forum-prose.md:337-349`）：这篇是谁在说／他手里最硬的三样材料是什么／读者读完上一段会问什么／哪一处是作者真正在意的地方。收尾一句很关键：「答案有了就动笔。不要继续给自己加写作任务。」——清单被刻意压短，避免清单本身变成新的表演。

### 2.3 加载纪律与冲突优先级

- 按任务读取（`SKILL.md:40-48`）：命中什么文体读什么参考文件，且「不要为了保险一次加载全部参考文件」。
- 冲突优先级表（`SKILL.md:50-60`）五级：用户明确指定 → 作品对现实的承诺 → 相关专门文件 → 默认散文写法 → `revision.md` 与脚本提醒。并写明「检查脚本只能执行已经写明的硬禁令，警告项不能替作者决定文体」。

### 2.4 事后脚本门禁

- `SKILL.md:158`：「长稿可以保存为 Markdown 或文本后运行 `scripts/check_prose.py <稿件路径>`。脚本失败就继续修改，直到禁用项清零。」
- `SKILL.md:138`：「下面几项覆盖标题、小标题、正文、图片说明和引用转述。命中一项就不能交稿。」
- `revision.md:160`：「原话命中禁令时改成转述。**禁用项没有清零，不能交稿。**」
- `check_prose.py:635`：`return 1 if failures else 0`——只有硬失败项影响退出码。完整语义是三值：`0` = 无硬失败（**只有警告也是 0**，已实测确认）；`1` = `failures` 非空；`2` = 读文件 `OSError`/`UnicodeError`（`:397`）或汉字数为 0（`:403`），argparse 缺参数同样是 2。
- 脚本实际是**四层**而不是两层：预处理层（`mask_non_prose`）、硬失败层（输出标题「需要修改」）、警告层（输出标题「需要人工判断」）、统计层（`:612-620`，无论成败都打印汉字数 + 12 个计数器，两者皆空时打印「未发现这份**检查器覆盖的**问题」，`:633` 的限定词本身即承认检测面有限）。

但它有三个「软」的地方：脚本在文档里是「可以」运行而不是必跑；运行它需要模型具备执行能力与文件权限；它检查的是**成稿**，对起草阶段的材料门槛毫无作用。

### 2.5 这套机制的结构性弱点（对我们自己设计的价值）

1. **门禁是自证式的。** 五件材料只要求「先在内部逐条写出」（`SKILL.md:26`），并「不要把这些内部检查交给用户」（`SKILL.md:36`），交付时也「不要展示内部提纲、规则检查和创作过程」（`SKILL.md:162`）。整套流程没有任何必须留下的证据产物，也没有外部校验点。
2. **「内部」与「不许展示」叠加，等于不可审计。** 用户无法区分「模型真的清点了五件材料」与「模型跳过了这一步」。这是我们可以直接改进的位置：把材料清点做成一份**必交的、可被机械检查的结构化产物**（例如动笔前先输出一份材料台账，或让脚本以退出码强制要求台账存在），而不是要求模型「在心里」做。
3. **两份清单之间没有交叉校验。** `forum-prose.md:341` 只要求「最硬的三样材料」，与 `SKILL.md:26` 的「五件」不一致（三 vs 五），也没有说明三与五的关系。
4. **文档内部有未同步的条文。** `SKILL.md:3`（frontmatter description）仍写「成稿正文严禁冒号、破折号」，而正文 `SKILL.md:147` 已经把冒号改为分级（引出直接原话放行）。frontmatter 是模型最先读到的部分，等于让最旧的版本先入眼。

### 5.1 六条矛盾的实际形态

需要先纠正一个前提：这六条**不是**「lieflat 判为不是 AI 痕迹 vs human-writing 绝对禁止」的同构对立，两侧的立场强度并不一样。逐条列出原文。

| # | 特征 | lieflat（按 283 万字实测） | human-writing（原文位置） |

| 1 | 句内同构排比 | **明确不是 AI 痕迹，且列为硬约束不得改**。同字开头两项 AI 2.35 / 人类 3.87 = **0.61×**；三项 0.95×；结论「句内人类更多，只有句间成立」。`SKILL.md` L79 列入「不作为改写理由」表，L451 验收清单要求「有没有改掉句内的同构排比……必须保留」 | 绝对禁止：「不写三项以上的同构排比……两项为限，第三项必须换一种说法或者删掉。」（`SKILL.md:143`）；脚本按「同一句内三个以上小句用同一个开头」告警（`check_prose.py:276-297`） |

### 5.2 human-writing 自己怎么解释这件事

### 5.3 它有没有声明判据是「像不像一个具体的人在说话」而不是统计频率

有，而且是仓库级、入口级、多处一致的声明；但它**从未显式对比统计判据**，也从未说「统计频率不是判据」这句话。分别说明。

**声明「像不像一个具体的人」的原文（四处，指向同一判据）：**

1. 仓库 description（GitHub API `repos/KKKKhazix/human-writing`.description）：**「让 AI 写的中文读起来像一个具体的人在说话。通用创作与改稿 Skill，开箱即用。」**
2. `README.md:20`：「让模型写出来的文章读起来像一个具体的人在说话——知道一些事，有判断，偶尔岔开一句，还能接回来。」
3. `SKILL.md:8`：「读者应当感觉对面有一个具体的人。这个人知道一些事，也有不知道的地方。」
4. `dist/human-writing-lite.md` 收尾自查：「哪一段像模型在完成写作任务就改掉，哪句话说得比材料大就删掉。」（`revision.md:192-204` 的「最后冷读」同构：「哪一段像人在处理一个问题，哪一段像模型在完成写作任务。」）

**禁的是「动作」而不是「字面」（这是它替代统计判据的实际机制）：**

- `SKILL.md:140`：「先明白一件事。这里禁的是修辞动作，不是字面。把一个禁用句式换一套字继续做同一个动作，仍然算命中。」
- `SKILL.md:10`：「不要把『活人感』理解成口头禅、粗口、错别字和网络梗。它首先来自**材料**，其次来自**说话位置**，最后才是**语气**。」——判据的排序是「材料 → 位置 → 语气」，没有频率的位置。
- `README.md:65`：「1.0 用字符串禁令拦 AI 味……有效，但模型会换一套字面继续做同样的事。……**读者认的是姿势，不是字。**」

**它唯一的统计学成分，以及这个成分的成色：**

- `CHANGELOG.md:21`：「新增统计层，句长变异系数过低警告、连词密度过高警告（**阈值依据 CCL 2023 人机中文对照研究**）。」
- 代码对应两处：`check_prose.py:540`（`cv_result[0] < 0.42` → 警告）、`check_prose.py:519`（`total_han >= 600 and len(conjunction_hits) * 1000 / total_han > 7` → 警告）。
- 但 `check_prose.py` 全文**没有任何注释、常量名或帮助文本引用这份研究**：`0.42` 与 `7` 都是裸数字，脚本的 docstring 只有一句「检查中文成稿的硬禁令与常见模型化形状。只报警，不自动改文。」（`check_prose.py:2`）。`sentence_length_cv` 的 docstring 也只写断言「人写的长短句差距大，模型的句长彼此接近」（`:301`）。独立逐文件核对确认：脚本与全部 references **零文献引用**，`forum-prose.md:148-158` 讲同一批「可以直接量出来的毛病」时同样零引用。阈值是相对篇幅缩放的（`:519,532,547,556,567`），这一点反而比 CCL 的引用更可核验。
- 我尝试用公开检索定位「CCL 2023 人机中文对照研究」：CCL 2023（第二十二届中国计算语言学大会）确实存在，也有同类的人机语言对比论文（例如 [A Comparative Study of Language between Artificial Intelligence and Human: A Case Study of ChatGPT](https://d.wanfangdata.com.cn/conference/ChNDb25mZXJlbmNlTmV3U3F1aWNrEiAyN2NmYzRmMWEwY2RlNjk2ZTcxYjc4ZWQ2MjAyM2E5YhoIbnVqZ2lxcjE%3D)、[Lexical Complexity Controlled Sentence Generation](https://aclanthology.cn/2023.ccl-1.56/)），但 `human-writing` 没有给出论文题名、作者或链接，**无法把这句「依据」锁定到任何具体文献**。
- 结论：`human-writing` 的统计依据目前不可核验，且只作用于警告层——`check_prose.py:635` 明确「只有 failures 才返回 1」，两个统计警告不阻止交稿。所以它不是「统计判据 vs 统计判据」的争论，而是**「修辞动作判据」对「触发标记的频率判据」**。

**一个有意思的会合点**：lieflat 自己也声明过判据不是频率。它在 `SKILL.md` L84 写「规则的依据是触发标记可定位，不是频率高低」，`README.md` L98 称方法为「算子可定位性」。也就是说，两家在「判据不是频率」这一层其实是一致的，分歧在于**用什么替代频率**：lieflat 用「可定位的形态算子 + 实测倍率作为收录门槛」，human-writing 用「这个动作是不是在替作者抬价／代替材料」。

**因此这场矛盾的准确表述是**：lieflat 用 283 万字回答「这个特征在 AI 与人类文本中的出现率是否不同」；human-writing 回答的是另一个问题——「这句话是不是一个具体的人在他那个位置上会说的话」。后者根本不引用前者，也不承认前者的判据类型，所以两者不是两个矛盾的数据结论，而是两套不互评的判据空间。这不构成 human-writing 的辩护，只是它的事实立场。

### 5.4 references/revision.md 与 scripts/check_prose.py 怎么处理误伤

两边都在防误伤，但机制完全不同：`revision.md` 用**人工分层的书面豁免**，`check_prose.py` 用**机器分层 + 语境启发式**。逐项给代码与原文。

**`revision.md` 的误伤机制（七种）：**

1. **本义豁免**：路标词「文字确实在说楼层、数量或原句本义时保留」（`revision.md:150`）；借喻「本义已经清楚，一个也不用放回」（`:80`）；抽象名词配动词「文章真的在写具体事物时不受影响」（`SKILL.md:144`，同位条款 `:151`）。
2. **词表分级**：27 条「绝对禁词」 vs 14 条「只做语境检查」的词（`revision.md:152,154`，与 `check_prose.py:20-65` 的 `HARD_JARGON` / `CONTEXT_JARGON` 一一对应）。语境词的判定说明写得很具体：「它们确实表示化学沉淀、排版对齐、游戏战术、房产或艺术评论里的想象余地、控制回路、『不丢人』等本义时保留；只是在给普通事情抬价时改写。」
3. **抒情词有条件保留**：「安放、抵达、微光、褶皱……写具体事物时都是好词，用来给抽象概念穿衣服时删掉。『』括起来的自造短语也一样，**一篇里出现三处以上，多半是在造金句**，拆掉。」（`revision.md:156`）——用密度而不是单次出现作判据，这本身就是防误伤。
4. **文体豁免**（最强的一条）：「下面七遍默认用于现代白话散文。诗歌、剧本、人物对白和实验写作**只执行事实或设定边界、用户明确要求与硬禁用项**，其余检查服从具体文体。不要为了让诗歌主干完整、让对白像说明文，改坏原本成立的作品。」（`revision.md:7`，同位 `:86,190`）
5. **比喻按套数而不是按次数**：「短距离出现三套时先全部还原成本义。」（`revision.md:80`）——一次比喻不触发。
6. **用户指定优先**：「用户指定的题目自带这类大词时，标题照用户的写，这条只管正文和结尾。」（`revision.md:176`）
7. **原话的处置是转述而非引号豁免**：「原话命中禁令时改成转述，不能靠引号保留。」（`SKILL.md:152`、`revision.md:160`）——这一条是主动拒绝一种常见的误伤豁免。

**`check_prose.py` 的误伤机制（八种）：**

1. **非散文内容整体屏蔽**：`mask_non_prose()`（`:224-241`）把 frontmatter、代码围栏、行内代码、Markdown 链接、URL、HTML 标签全部换成空白，**同时保留字符位置与换行**，所以行号仍然准确。这直接实现了文档里的「网址、代码与机器字段除外」。
2. **冒号分级（唯一的启发式分级）**：`:411-419` 逐处看冒号后两个字符，`tail[:1] in ("「", "『", "“", "‘", '"')` → 归入 `quote_colons`；其余 → `failures`。引号冒号降为警告，且警告文本要求人工确认：「确认引号里确实是原话，且不是提示性用法。」（`:427-429`）
3. **硬禁词与语境词去重**：`:439-450` 先算 `HARD_JARGON` 的命中区间 `hard_spans`，再把与之重叠的 `CONTEXT_JARGON` 命中剔除，避免同一个词被报两次、也避免「迭代闭环」同时触发「闭环」。
4. **长词优先匹配**：`non_overlapping_terms()`（`:244-254`）按词长降序匹配并占用区间，`打开想象空间` 不会被拆成 `想象空间`。
5. **变形族只警告**：`PIVOT_PATTERNS`（`:97-105`，字面翻案）→ `failures`；`SEMANTIC_PIVOT_PATTERNS`（`:107-119`，以为……其实、回头才发现、跨句表面／看似、A 不重要重要的是 B 等 12 个变形）→ `warnings`，且与已命中的 `PIVOT` 区间去重（`:480-489`）。警告文本本身写了豁免条件：「先立误解再推翻就改成正面陈述，**正常用法保留**。」（`:493`）这修正了 1.0 时代「换字的翻案句蒙混过关」与「正常句被误杀」两头的问题（`CHANGELOG.md:21`）。
6. **阈值随篇幅缩放 + 最小覆盖面**：`highlight_limit = max(3, total_han // 700)`（`:532`）、`marker_limit = max(2, total_han // 900)`（`:547`）、`left_limit = max(2, total_han // 1200)`（`:556`）、`dense_de_limit = max(1, total_han // 1500)`（`:567`）、短句连排需 4 段（`:357`）、单句段比例检查需段落数 ≥10 且比例 ≥75%（`:578-584`）。短文本不会因为绝对计数低而误报。
7. **单点命中不报，需重复或密度**：抒情词需 ≥2 处才报（`:504`）、「」高亮需超过限额（`:533`）、段落开场重复需同一开场 ≥4 次（`:595`）、排比需同句内 ≥3 个小句同头（`:276-297`）。
8. **报错量截断**：排比、名词化各只列前 4 条（`:497,512`），冒号、路标等每类最多列 8 个行号（`:421,425`），避免警告刷屏掩盖重点。

**此外，`revision.md:158` 有一条防止「脚本偷偷加规则」的一致性纪律**：

> 「检查脚本里的硬禁词必须与本节完全一致。增加或删除硬禁词时，同一轮修改脚本，**不能让脚本偷偷多出一套规则**。」

**这条纪律已经被违反，且没有任何机制能发现。** 静态核对（脚本词表 × `revision.md` 词表）发现三处不同步：

1. `LYRIC_WORDS`（`check_prose.py:67-77`）只有 9 个词，缺 `revision.md:156` 点名的 **`锋利`、`坚硬`、`柔软`**（三词在脚本中 0 命中）。
2. `METAPHOR_FIELDS`（`:192-200`）的七组借喻场里没有 `revision.md:82` 点名的 **`抽屉`、`钥匙`**（脚本 0 命中）；`底座` 只作为黑话 `技术底座`/`公共底座` 出现，不在借喻场内。
3. 严重度不一致：「三项以上同构排比」在 `SKILL.md:143` 属于「成稿绝对不能出现」，脚本只给**警告**（`:496-501`）——脚本比文档松一档。

值得说明的是第 3 条的方向：从误伤控制看「松一档」是**正确**的（句内排比正是 lieflat 实测为人类更多的特征，见 5.1），但文档没有承认这个降级，读文档的人会以为它是硬失败项。这说明这套规则缺一个「文档词表 ↔ 脚本词表」的自动一致性校验，而 `revision.md:158` 只把它写成了人工纪律。`CHANGELOG.md:21` 记录过三处误伤修复（「不丢人」不再触发硬停词、`打法`/`想象空间`/`闭环` 移入语境判断词、引出原话的冒号降为警告），说明这类不同步此前确实发生过，而上面三处是这次修订之后仍然残留的。

`SKILL.md:60` 与 `revision.md:190` 补上权属：「检查脚本只能执行已经写明的硬禁令，警告项不能替作者决定文体」／「脚本只负责发现形状，不能判断文章有没有人。警告项需要回到材料与说话位置人工判断。」——这两句是**拒绝把脚本的统计输出当作判据**的明确表述，也是 human-writing 面对「误伤」问题的最终答案：机器只报形状，判断权交回人／作者。

**实测到的误伤面（独立子代理构造 13 组样本运行脚本所得）：**

| 样本 | 结果 | 说明 |
|---|---|---|
| `他说：「我不去了。」` | 警告，exit 0 | 引号豁免生效 |
| `他说：我不去了。`（无引号） | 硬失败 | 与 `SKILL.md:147` 一致 |
| `核心是：` | 硬失败 | 提示性冒号 |
| `：` 后隔 3 个空格再接 `「` | **硬失败** | 豁免窗口只取冒号后 2 个字符再 `lstrip()`（`:414`），空格先把窗口吃掉，豁免失效 |
| `——` | 报 2 处 | 逐字符匹配，不合并 |
| `10:30` 时间、`2019—2021` 年份区间、Markdown 表格里的 `:` | 硬失败 | `mask_non_prose` 只屏蔽 frontmatter／代码／链接／URL／HTML，不管这些 |
| 纯英文句子里的 `colon:` 与 `—` | 硬失败 | 遮蔽只按上述六类模式 |
| `这栋楼还有一层没有装修` | 不报 | `还有一层` 的 16 词 lookahead 本义放行（`:148`），是全文唯一的「本义白名单」 |
| `还有一层是，他其实并不想去` | **不报（漏报）** | 「是」不在那 16 个词里，真路标漏掉 |
| `沉淀` ×3、无硬禁词 | 「需辨语境词 3」，exit 0 | 语境词只提醒不阻断 |
| 引号内的 `说白了`／黑话／破折号 | 硬失败 | 有意设计，对应 `SKILL.md:152`「不能靠引号保留」 |

这组实测还确认了一个设计事实：句内同构排比的判据是**「相邻小句前两个字相同」**（`check_prose.py:290`），不是句法同构，属于近似启发式；而「抽象名词配具体动词」在代码里**没有任何语法级实现**，只有 `LYRIC_WORDS` 词表（≥2 次才报）与 `metaphor_cluster`（800 字符窗口内 ≥3 套借喻场才报）两个代理指标——`revision.md:144` 举的「时间保管、岁月打磨、焦虑显形、孤独发芽」在脚本里没有对应正则。

### 5.5 这给本项目生成态的启示

1. **判据类型要写清楚，否则矛盾无法收敛。** lieflat 的问题是「频率判据」被当成「AI 痕迹判据」；human-writing 的问题是「修辞动作判据」被当成「AI 痕迹判据」（它把借喻词表、破折号、名词化一起归到「清 AI 味」的标题下，`SKILL.md:136` 的标题就是「成稿绝对不能出现」，`README.md:34` 更把「冒号滥用、破折号」与「常见 AI 黑话」并列）。两家都犯了同一个归类错误。我们应当把两类判据分开命名：**「统计上不像人」（有倍率与置信区间，需实测）** 与 **「动作上不像人」（有位置与材料依据，需可定位的触发形态）**，并分别标注证据强度。
2. **吸收 lieflat 自我修正的那条纪律**：当人类组内部差异过大时（如句中总说分说冒号，人类内部 6.6 倍），就**明确列入不改**，而不是降级为警告。`human-writing` 没有这条纪律，所以它的禁令可以是零证据的。
3. **严重度要分层，且只有一层能阻断。** `human-writing` 的 `failures / warnings` 两级 + 退出码语义（`:635`）比 lieflat 的「11 条按优先级排序」更接近可自动化；建议保留这个设计，但把「材料门槛」这类生成态硬停做成**可验证的证据产物**，而不是 `SKILL.md:26` 那种「先在内部写出」的自证。
4. **生成态要有自己的规则集，不要复用清理清单。** `human-writing` 的 `revision.md:3`（「它不能参与第一稿生成」）与 `SKILL.md:48`（正向目标为主，禁令留到成稿后）是这个项目最值得直接抄的两句设计决策。

## 6. 核验方式与已知局限

**核验方式**：`git clone --depth 1 https://github.com/KKKKhazix/human-writing.git` 得到工作副本并 `git rev-parse HEAD` 锁定 SHA；`human-writing/VERSION`、`CHANGELOG.md`、`README.md` 与全部 references、dist、agents、scripts 逐文件通读；脚本除通读外另按 `grep -n "^def |^[A-Z_]* = "` 核对结构与常量；`gh api repos/.../commits/main` 与 `gh api repos/.../issues` 核对日期、star 数、license 与 issue 线索。lieflat 侧由独立子代理以 `gh api` + `curl -sL raw.githubusercontent.com/.../<SHA>/<file>` 取数，并以文件字节数与 `git/trees/main?recursive=1` 逐一致来确认读取的就是所审 SHA（README.md 19587 / SKILL.md 28382 / RESEARCH.md 18530 / LICENSE 1064）。本报告未使用 `web_fetch`（本机被 DNS 代理拦死），`web_search` 仅用于尝试定位 human-writing 引用的 CCL 2023 文献，未用于任何事实结论。

**已知局限**：

1. lieflat 的语料未公开（`README.md` L246 自陈「这是本研究的实质缺陷，非免责说明」），本报告对它的引用是**其自述数字**，无法独立复核。
2. `human-writing` 的 issue 区（#1–#9）里**没有**关于与 lieflat 矛盾的讨论：`#5`（「提示词这ai味太浓了」）与 `#8`（「一点心理描写和神态描写都没有」）都只有正文、无作者回复，因此无法从维护者互动中获得对第 5 节的补充解释。
3. `check_prose.py` 的分级与误伤行为由一个独立子代理以 13 组构造样本实测确认（见 5.4 表），但这些样本是本次研究为验证机制而设计的，不是该项目的测试集——`human-writing` 仓库里没有任何测试文件（issue #1「test: cover check_prose CLI behavior」仍处于 open 状态，说明作者自己也知道这一点）。
